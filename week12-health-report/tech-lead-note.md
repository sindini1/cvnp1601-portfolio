The health report script collects disk usage with df -h, inode usage with df -i, memory with free -h, load and uptime, five vmstat samples, CPU core count, and listening TCP services with ss -tlnp. Every report starts with a header that prints the hostname and the exact timestamp so the file identifies which server produced it and when. The script writes a unique timestamped file into ~/reports/ each time it runs. The final cron schedule is daily at 6:00 AM with a PATH line so cron can find the standard commands. The command that proves the report ran is ls -la ~/reports/health_*.log together with a tail of the newest file showing the hostname and current timestamp in the header. Based on the captured evidence the disk Use% is well under 80 percent, available memory is healthy, load averages are low relative to the core count, and the listening services match the expected set for this lab VM. The server appears healthy.

I can explain why the available column in free -h is the better health metric than free. Linux uses idle RAM as reclaimable disk cache, so a low free number does not mean the system is out of memory. Available shows what can still be given to new processes without swapping.
