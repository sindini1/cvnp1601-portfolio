pwd
What: print working directory
Example: pwd
Note: always run this before a screenshot so location is proven

ls
What: list files
Flags: -l long, -h human sizes, -a include hidden
Example: ls -lh /var/log
Note: read permissions before you touch a file

cd
What: change directory
Example: cd /var/log    cd ~    cd ..    cd -
Note: cd etc fails from home because that is relative. Use /etc

find
What: search by name from a starting path
Example: find /etc -name "*.conf" 2>/dev/null | head -10
Note: Permission denied is often the system protecting files, not a broken command

grep
What: search text inside a file
Flags: -i ignore case
Example: grep -i "error" /var/log/syslog
Note: you are filtering evidence, not deleting anything

head
What: show the first lines
Flags: -20 first 20 lines
Example: grep -i "error" /var/log/syslog | head -20
Note: keeps huge logs readable

wc
What: count
Flags: -l count lines
Example: wc -l /var/log/syslog
Note: use it to prove how much you found

pipe |
What: send output of one command into the next
Example: grep -i "error" /var/log/syslog | wc -l
Note: left command runs first

redirection >
What: write output to a file, overwrite if it exists
Example: grep -i "error" /var/log/syslog > errors.txt
Risk: can wipe a file you still needed

append >>
What: add output to the end of a file
Example: grep -i "warning" /var/log/syslog >> errors.txt
Note: use this when you want to keep old evidence

stderr suppression 2>/dev/null
What: hide error messages
Example: find /etc -name "*.conf" 2>/dev/null
Note: denials are still happening, you just are not printing them

=== Week 2 ===

vim
What: terminal editor with modes
Commands: i insert, Esc normal, :w save, :wq save and quit, :q! quit without saving, /Status search, dd delete line, u undo
Risk: :wq saves whatever is on screen. Use :q! if the edit is wrong.

nano
What: simpler terminal editor
Commands: Ctrl+O save, Ctrl+X exit
Note: better for a short note when you do not want vim modes

grep -r
What: search a directory tree
Example: grep -r "PermitRootLogin" /etc/ssh/ 2>/dev/null

grep -v
What: drop matching lines
Example: grep -v "^#" /etc/ssh/sshd_config

grep -iE
What: extended search, ignore case
Example: grep -iE "error|warning" /var/log/syslog | head -10

awk '{print $N}'
What: print field N
Example: grep "Accepted password" /var/log/auth.log | awk '{print $1, $2, $3, $9}'

awk -F:
What: split on colon
Example: awk -F: '{print $1, $7}' /etc/passwd

uniq -c
What: count adjacent duplicate lines
Example: sort src-ips.txt | uniq -c | sort -rn
Risk: without sort first, repeats do not group

=== Week 3 ===

useradd -m -s
What: create a user with a home directory and a login shell
Example: sudo useradd -m -s /bin/bash devuser

usermod -aG
What: append a supplementary group
Example: sudo usermod -aG developers devuser
Risk: usermod -G without -a replaces the extra groups

visudo / sudoers
What: edit sudo policy
Example: devuser ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart nginx
Note: drop-in files under /etc/sudoers.d need mode 0440

=== Week 4 ===

ls -la string
  pos 1  - file  d directory  l symlink
  2-4    owner rwx
  5-7    group rwx
  8-10   other rwx
  a + on the end means an ACL is there. run getfacl.

octal
  r=4 w=2 x=1
  chmod 750 file    owner rwx, group r-x, other none

special bits
  chmod +t /project     sticky, only owner/root can delete
  chmod g+s /project    SGID, new files inherit the dir group
  chmod u+s binary      SUID on binaries only
  kernel ignores SUID on scripts that start with #!

ACL
  getfacl /project
  setfacl -m u:carlos:r-x /project
  setfacl -x u:carlos /project

why not these
  chmod 777             every account gets rwx
  usermod -aG for a one week contractor

=== Week 5 ===

apt update
What: refresh the local package list from the repos
Example: sudo apt update
Note: run this before install so you do not get a stale version

apt install -y
What: install a package and auto-answer yes
Example: sudo apt install -y nginx
Note: -y is required in scripts because a script cannot type yes

apt remove
What: remove package binaries, keep config files
Example: sudo apt remove nginx

apt purge
What: remove the package and its config files
Example: sudo apt purge nginx
Note: use purge when you want a clean-state reinstall

apt autoremove
What: remove packages that were only installed as dependencies
Example: sudo apt autoremove -y
Note: leftovers can stay after a purge if you skip this

dpkg -l
What: show package status
Example: dpkg -l nginx
Note: ii = installed, rc = removed with config left, un or missing = not installed

systemctl lifecycle
What: start, stop, status, enable, disable
Example: sudo systemctl start nginx
Example: sudo systemctl stop nginx
Example: sudo systemctl status nginx
Example: sudo systemctl enable nginx
Example: sudo systemctl disable nginx
Note: start is now. enable is after reboot. they are separate.

enable --now
What: enable for boot and start immediately
Example: sudo systemctl enable --now nginx
Note: production default when you want both states at once

systemctl is-active --quiet
What: check running state with no printed text
Example: systemctl is-active --quiet nginx && echo ok
Note: exit 0 means active. use this in scripts instead of parsing status

$?
What: exit code of the last command
Example: systemctl is-active --quiet nginx; echo $?
Note: 0 is success. anything else is failure

shebang
What: #!/bin/bash on line 1
Note: must be the first line. it picks the interpreter when you run ./script.sh

Risk / security
A service script that skips verification can report done while nginx is inactive, disabled, or masked.
Use is-active --quiet and exit 1 so a dead service fails the job instead of going to production.
Read the Loaded line. masked means systemd is blocking the unit on purpose. do not assume the package is corrupt.
