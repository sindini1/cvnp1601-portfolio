backup_etc.sh archives /etc into /var/backups/etc/etc_TIMESTAMP.tar.gz and writes every major step to /var/log/backup_etc.log. Paths sit at the top as quoted variables so a later change does not have to be hunted through the file. log() stamps the time and uses tee -a so the same line hits the screen and the log. That beats a plain echo, because terminal output is gone after the session closes and a redirect-only echo hides the run from the person watching it.

The archive step is tested directly in an if. If tar exits non-zero, the script logs ERROR and exits 1. It does not pipe tar into tee. A pipe would score tee's exit code, which is how a trainee got a success line after Permission denied. Git history on the Linux box has two commits: the logging script, then a verification ls of the archive path. That is the audit trail. A teammate can see what changed without watching me type it.

The risk this cuts is a silent bad backup. Without a timestamped log and a non-zero exit, cron or the next tech can think /etc was saved when the archive is empty or incomplete. During an outage that is the copy you restore from. A false success line is worse than a failed run you can see.
